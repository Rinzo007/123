# Архитектура Transit Planner

## Принцип независимости

Ни один модуль нового ядра не импортирует od/, passenger_flow/, routes.py, models.py или другие старые компоненты репозитория.

## Расчётный поток

City -> zones -> OD -> mode choice -> route choice -> assignment -> crowding -> analytics

## P2: дорожный граф

Overture transportation segment/connector adapter -> RoadRecord -> road_builder -> RoadGraph

## P3: спрос и маршрутизация

City -> Demand zones -> Gravity OD -> Zone-to-stop access -> TransitRouter -> Journey

## P4: распределение спроса

OD pair -> mode choice -> route choice -> section flows -> capacity -> crowding penalty -> repeated assignment

## P5: аналитика

AssignmentResult -> stop analytics -> section analytics -> accessibility -> passenger-km -> economics

## Сценарии

ScenarioDefinition содержит вариант сети, спрос и параметры расчёта.

ScenarioRun содержит результат моделирования, аналитику и экономику.

ScenarioComparison содержит только измеряемые различия между двумя запусками: базовые значения, альтернативные значения и абсолютную/относительную разницу. Никаких рейтингов и встроенного выбора лучшего сценария нет.

## Веб

Vanilla TypeScript + Vite/Rollup + MapLibre GL JS 5.24 отвечает за интерфейс, карту и редактирование. IndexedDB хранит проекты и кэш наборов данных, Web Workers выполняют неблокирующие клиентские предрасчёты. Серверный Python/FastAPI остаётся авторитетным источником транспортных расчётов.

FastAPI отвечает за транспорт между интерфейсом и доменным ядром.

Расчётные модули не зависят от браузера.

## Производительность

Текущая реализация является детерминированным базовым вариантом. Следующие оптимизации: пакетная маршрутизация OD, кэширование состояний, пространственные индексы, многопроцессное распределение и векторизация.

## Порядок разработки

P0 — каркас и границы.
P1 — доменная модель сети.
P2 — дорожный граф и городские данные.
P3 — OD и мультимодальная маршрутизация.
P4 — распределение спроса и перегруженность.
P5 — аналитика, экономика и сценарии.
P6 — веб-редактор карты.
P7 — экспорт, производительность и развёртывание.


## Веб-архитектура

Структура интерфейса следует поставленной референсной архитектуре: карта и редактирование отделены от представления сети и результатов оценки, вычисления могут выполняться в Web Workers, а данные проекта и наборы данных кэшируются в IndexedDB.

Клиентские Worker-ы используются для быстрого предрасчёта и отзывчивости интерфейса. Численные результаты городской модели, назначения спроса, экономики и сравнения сценариев подтверждаются Python backend.

Клиентский entry — один `src/app.ts`: ручной DOM через `document.createElement`/`innerHTML`, MapLibre и делегирование событий; отдельные UI-компоненты Svelte не используются.

Источником городских пространственных данных остаётся Overture Maps.


### Соответствие референсу

Frontend использует один Vite/Rollup entry без UI-фреймворка, MapLibre GL JS 5.24.0, собственное IndexedDB-хранилище `takt/kv`, gzip через `CompressionStream`, reference Web Worker runtime и бинарный `TKBL`-кэш геометрии. Городские пакеты поддерживают manifest с SHA-256 и размерами файлов.
