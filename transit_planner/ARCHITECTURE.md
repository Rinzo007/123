# Архитектура Transit Planner

## Принцип независимости

Ни один модуль нового ядра не импортирует od/, passenger_flow/, routes.py, models.py или другие старые компоненты репозитория.

## Расчётный поток

City -> zones -> OD -> mode choice -> route choice -> assignment -> crowding -> analytics

## P2: дорожный граф

GeoJSON / OSM / Overture adapter -> RoadRecord -> road_builder -> RoadGraph

## P3: спрос и маршрутизация

City -> Demand zones -> Gravity OD -> Zone-to-stop access -> TransitRouter -> Journey

## P4: распределение спроса

OD pair -> mode choice -> route choice -> section flows -> capacity -> crowding penalty -> repeated assignment

## P5: аналитика

AssignmentResult -> stop analytics -> section analytics -> accessibility -> passenger-km -> economics

## Сценарии

ScenarioDefinition содержит вариант сети, спрос и параметры расчёта.

ScenarioRun содержит результат моделирования, аналитику и экономику.

ScenarioComparison содержит только измеряемые различия между двумя запусками: базовые значения, альтернативные значения и абсолютную/относительную разницу. Никаких рейтингов и встроенного выбора лучшего сценария нет.

## Веб

React + MapLibre отвечает за карту и редактирование.

FastAPI отвечает за транспорт между интерфейсом и доменным ядром.

Расчётные модули не зависят от браузера.

## Производительность

Текущая реализация является детерминированным базовым вариантом. Следующие оптимизации: пакетная маршрутизация OD, кэширование состояний, пространственные индексы, многопроцессное распределение и векторизация.

## Порядок разработки

P0 — каркас и границы.
P1 — доменная модель сети.
P2 — дорожный граф и городские данные.
P3 — OD и мультимодальная маршрутизация.
P4 — распределение спроса и перегруженность.
P5 — аналитика, экономика и сценарии.
P6 — веб-редактор карты.
P7 — экспорт, производительность и развёртывание.
