# Архитектура Transit Planner

## Принцип независимости

```text
transit_planner
    ├── domain
    ├── demand
    ├── simulation
    └── api
```

Ни один модуль нового ядра не импортирует `od/`, `passenger_flow/`, `routes.py`, `models.py` или другие старые компоненты репозитория.

## Целевой поток

```text
City data
  -> zones / places / road graph
  -> Network
  -> Demand
  -> Mode choice
  -> Transit routing
  -> Assignment
  -> Crowding
  -> Analytics
```

## Контракты

**City** описывает территорию и источник данных.

**Network** описывает инфраструктуру и предложение перевозок.

**DemandMatrix** описывает потенциальные поездки между зонами.

**SimulationResult** содержит вычисляемый результат и не зависит от веб-интерфейса.

**API** только преобразует HTTP-запрос в вызов доменного ядра.

## Порядок разработки

P0 — каркас и границы.

P1 — доменная модель сети.

P2 — дорожный граф и городские данные.

P3 — OD и мультимодальная маршрутизация.

P4 — распределение спроса и перегруженность.

P5 — аналитика и сравнение сценариев.

P6 — веб-редактор карты.

P7 — экспорт, производительность и развёртывание.
